# Use a visual-guided mixture prior for the Stage-A Einstein radius

The System Inspector will preserve a Visual Einstein-Radius Hint for every `model` disposition and a new Pipeline Release will deterministically convert eligible `high` or `medium` hints into a Stage-A prior with an 80% truncated-normal core and a 20% uniform escape component over the baseline `[0.5'', 3.0'']` support. The core is centred on the hint with `sigma = min(0.2 * hint, 0.2'')`; exploratory fits showed that the broader core allowed sampling to settle too readily in local optima, while the uniform component preserves non-zero prior mass across the full support when a hint is inaccurate. `low` confidence and hints unsupported by the baseline interval retain the baseline uniform prior. This changes the numerical search measure, not the SIE+shear physical model, and the hint remains an empirical prior derived from the same VIS image used by the likelihood.

The inspector must also preserve the plausible range, confidence, geometric basis, and visible deflector centre. The Hint-Anchor Image Family is the secure family that best constrains the tangential critical scale; additional source clumps may produce Compatible Lensed-Image Families and are not competing interpretations merely because their image radii differ. A Competing Lens Interpretation exists only when the assignments cannot coexist under one dominant deflector and simple mass-scale topology.

The prior and its versioned Visual-Prior Provenance are materialized in the initial Stage-A attempt-local configuration. Invalid required hints are response-contract errors rather than silent fallbacks, the hint is never clipped or fixed, and a Visual-Prior Conflict is review evidence rather than an automatic retry or blocker. The workflow does not automatically rerun the uniform baseline, and `log Z` values from visual-guided and uniform priors must not be used as like-for-like evidence comparisons. Existing Lens Runs do not adopt the change in place; using it requires the new Pipeline Release and a fresh run from preflight. Calibration experiments are intentionally outside this implementation task.

The new release represents every configured prior explicitly as `prior_type`, `prior_settings`, and `limits`, matching TinyLensGpu rather than extending the old positional five-value tuple. A mixture is eligible only for a valid `model` hint with `high` or `medium` confidence and a point estimate inside `[0.5'', 3.0'']`; a valid `low` or out-of-support hint falls back to the baseline uniform prior, while malformed or internally inconsistent output requires response correction. The inspector schema, evaluator, mask command, and attempt preparation share strict decision validation, including lens identity and the conditional requirement that every `model` decision carry a complete hint.

Stage-A attempt 0 stores both the effective configuration and `visual-prior-provenance.json`, including the source hint, derivation-rule version, eligibility result, effective prior, and fallback reason. Later Stage-A attempts inherit that prior and reference the original provenance. Python exposes posterior-versus-hint diagnostics without a mechanical conflict threshold; scientific review may record `visual_prior_conflict`, but the disagreement alone cannot block progression.
