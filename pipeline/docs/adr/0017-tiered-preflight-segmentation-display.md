# Distinguish retained preflight segments by display prominence

Fresh preflight runs will keep ADR 0016's single authoritative Core-Seeded Segmentation unchanged: a deblended 2σ footprint remains maskable only when it overlaps a coherent 3σ core of at least five connected pixels. Among those retained segments, overlap with a coherent 4σ core of at least five connected pixels assigns the `strong` Segmentation Display Tier; all other retained segments receive the `weak` tier. Both Inspector and human-audit figures continue to draw the same complete retained 2σ footprints and IDs without adding core-pixel geometry, but strong segments use coloured solid contours and prominent IDs while weak segments use subdued dotted contours and smaller IDs. The six-panel audit canvas keeps its existing dimensions while reserving dedicated top and bottom margins for the title and tier legend; this layout-only adjustment does not change panel data, cutouts, or image scaling. The tier expresses detection reliability only and never determines deflector, lensed-image, contaminant, or unresolved class; it does not change `segmentation.fits`, ID maskability, or the Modeling Mask. This decision supersedes only ADR 0016's uniform-presentation choice, leaves the System Inspector's textual instructions unchanged, records the fixed display threshold and exact tier membership in `inspection_packet.v4`, and activates under the new `core-seeded-tiered-display.v1` Pipeline Release so existing Lens Runs remain immutable.

This display-only alternative was chosen after increasing the shared connected-pixel minimum and increasing deblend contrast both merged scientifically distinct structures in the diagnosed lens. Activation requires deterministic strong/weak classification and rendering tests, human inspection of regenerated three- and six-panel figures for the diagnosed lens and representative regression lenses, the complete fast test suite, and syntax checks; production-model comparisons remain external scientific validation and are not implied by deterministic test success.
