# Inspect the central three-panel prompt and retain the six-panel audit

Fresh preflight runs will give the System Inspector only the three central panels while retaining the existing six-panel figure, layout, and filename as a human-facing auxiliary artifact. The Inspector view preserves the former central 8″×8″ content plus one image pixel of context beyond the fixed 4″ circle on every edge (normally 0.1″, producing an 8.2″×8.2″ field); this makes axial as well as corner boundary crossings visible. The inspection packet explicitly identifies the two image roles so the human audit is never accidentally supplied to the model. A Boundary-Crossing Segment is defined by one segmentation ID having pixel centres on both sides of the fixed 4″ boundary. The System Inspector classifies every such segment as contamination without a morphology exception, and its reason must identify the affected IDs and this boundary-rule basis; deterministic code neither supplements a missed ID nor rejects the response for omitting one. This narrows the model's visual task and preserves the wide-field audit for humans, while deliberately accepting both model miss risk and the possibility that a true deflector or lensed-image segment crossing the boundary is excluded from the likelihood. The change requires a new Pipeline Release and fresh preflight; existing Lens Runs and their visual artifacts remain unchanged. The new release becomes current after deterministic tests and human inspection of generated figures, without waiting for a paid model comparison; the absence of a production-model three-panel versus six-panel regression remains a documented limitation.
