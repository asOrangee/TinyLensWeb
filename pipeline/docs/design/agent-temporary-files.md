# Lens Run agent 临时文件管理计划

状态：已实施并通过验证与独立审查（2026-09-07）。

## 已确认的决定

- 管理范围是 Lens Run 中 orchestrator 和所有专家主动创建的临时响应、草稿和辅助文件。开发调试文件与第三方库缓存不在此次范围内。
- 根目录固定为当前仓库根目录下的 `tmp/`，传递给专家的路径必须为绝对路径。本次不提供可配置的替代根目录；创建失败时明确报告错误，不自动改用其他位置。
- 每次调度会话创建唯一子目录，再按 lens 和阶段隔离。同一科学 Lens Run 在中断后恢复时，可以使用新的临时空间；临时文件不作为正式恢复依据。
- 响应成功登记为正式记录后删除对应草稿。校验失败时保留到修正完成；异常退出时保留并报告准确路径。本次不实现按时间自动清理。
- 三位 inspector 的响应须等整组成功登记后再清理。
- 通过 orchestrator 技能、Stage Expert 共享手册和启动器提示指定目录，不新增 Python 辅助模块、CLI 参数或提交路径校验。现有的结果目录外部响应约束保持有效。
- 一个 lens 正常结束时，包括科学原因导致的 `human_review`，删除它在当前调度会话中的剩余临时文件。操作异常仍保留并报告路径。清理失败只报告残留，不改变已登记的科学结论。
- 正式科学产物仍由现有命令写入 Lens Result Directory。程序为原子替换而创建的相邻 `.tmp` 文件保持现有位置，包括 JSON 和批次状态文件。
- 将仓库根 `/tmp/` 加入 `.gitignore`。

示意目录（具体命名仍可在实现中确定）：

```text
<repo>/tmp/<唯一调度会话标识>/<lens_id>/preflight/
<repo>/tmp/<唯一调度会话标识>/<lens_id>/stage-a/
```

## 实施前核实的现状与约束

- 实施前，Orchestrator 技能只要求临时保存 preflight 响应，没有指定位置。
- 六个 Stage Expert 共用 `stage-expert-loop.md`；实施前，该手册仅要求响应位于 Lens Result Directory 外部，并在提交后删除。
- `adjudication.py` 只校验响应位于当前结果目录外部；`inspector_synthesis.py` 没有统一临时目录边界检查。
- `scripts/run_lens_batch.sh` 已从脚本位置确定仓库绝对路径，但直接交互调用技能的入口也需要覆盖。
- 不同批次可能并行运行，不能只用 lens ID 区分临时空间。
- Inspector 和 synthesis 的返回响应由 orchestrator 保存；不扩大这些专家可读取的科学证据范围。
- 不完整的 preflight 必须按现有规则重做整组检查，不能凭遗留草稿拼接投票。

## 具体实施方案

### 创建和传递

- Orchestrator 负责临时空间的创建、分配和最终清理。批量启动器只在提示中提供已确定的仓库绝对路径及遵循统一规则的指令，不另建一套临时目录机制。
- 直接交互入口由 orchestrator 在创建文件前确定当前仓库根目录的绝对路径；不能把任意当前工作目录直接当作仓库根。
- 在 `<repo>/tmp/` 下用 `mktemp -d` 创建带随机后缀的 `lens-session.XXXXXXXXXX` 目录，避免并发或恢复会话重名。仅在确需临时文件时创建。
- 在会话目录内建立 `<lens_id>/preflight/` 和 `<lens_id>/stage-<stage>/`。阶段目录中的文件名包含 attempt 编号，以免不同尝试互相覆盖。
- 委派 Stage Expert 时提供它独占的绝对临时目录。替换专家沿用当前会话中该 lens × stage 的目录；新调度会话另建唯一目录。完整重跑为该 lens 分配新的唯一临时空间。
- Inspector 与 synthesis 的响应仍由 orchestrator 写入 `preflight/`；不改变它们的输入或输出职责。
- 路径规范要求临时空间位于实际仓库 `tmp/` 内，且处于 Lens Result Directory 外部；不得借助符号链接转移到其他位置。发现路径冲突或创建失败时报告并停止依赖该目录的操作，不自动选择替代目录。这些是 agent 操作指令，不增加提交入口的程序校验。

### 清理和恢复

- Stage Expert 确认响应成功登记后删除对应临时响应；校验失败时在指定目录内修正，不提前删除。
- Orchestrator 确认三个投票全部成功登记后删除整组临时响应；synthesis 成功登记后删除其临时响应。
- Orchestrator 确认 lens 达到 accepted M3 或科学 Human Review，且该 lens 的专家与命令均已结束后，清理当前会话中该 lens 的全部临时文件，包括剩余辅助文件。
- 删除前确认准确路径属于本会话、本 lens，且没有活动任务使用它；不得删除仓库 `tmp/` 根目录、其他会话目录或其他 lens 的文件。会话目录为空时可删除空目录。
- 操作异常时保留该 lens 的剩余临时文件，并在终止报告中给出绝对路径；正常清理失败时同样报告残留，不重做科学计算或改写正式决定。
- 恢复会话从正式结果读取进度，不复用旧临时响应，不扫描或清理历史遗留文件。旧 preflight 的部分草稿不能作为投票依据。

### 修改文件

1. `.codex/skills/lens-model-orchestrator/SKILL.md`：新增统一临时空间规则，覆盖创建、preflight 响应、委派、恢复和结束清理。
2. `.codex/skills/lens-model-orchestrator/references/stage-expert-loop.md`：将模糊的“结果目录外部临时文件”改为传入的绝对临时目录，并明确修正、成功提交和异常时的处理。
3. `scripts/run_lens_batch.sh`：在调度提示中传递仓库绝对路径，明确使用相同临时空间规则。
4. `.gitignore`：新增 `/tmp/`。
5. 本设计文档：实施后更新状态和实际验证结果。

六个 Stage Expert 的 TOML 已共同引用上述手册，不重复写六份路径规则。无需修改模型、评审 JSON schema、Python 提交实现或现有科学产物布局。

## 验收条件

- 审核两种启动方式都能明确确定仓库根目录，所有 agent 主动创建的临时文件都有指定归属；指令中不存在允许随意写入系统 `/tmp` 或工作目录的矛盾。
- 审核两次并行调度、同一 lens 恢复、同一会话中替换专家与完整重跑的目录分配规则不会混用不同运行的草稿。
- 审核投票整组提交、响应校验失败修正、成功清理、科学 Human Review 清理、操作异常保留等流程覆盖完整。
- 对启动器执行 `bash -n scripts/run_lens_batch.sh`，并运行已有的 `tests/test_run_lens_batch.py` 相关测试；只有实际行为变化使现有断言不再准确时才调整测试。
- 用 `git check-ignore` 检查仓库 `tmp/` 路径会被忽略，检查变更差异与格式。
- 不为文字规则建立模拟文件写入的测试，不为验证此次变更启动 GPU 建模；上述验证不等于保证大模型永远遵守目录规则。
- 不改变物理模型、数值算法、科学门限、重试预算或已存在的科学结果。

本计划是文件管理实施说明，不引入新的科学领域术语；暂不新增术语表条目或 ADR。

## 实施验证结果

- 实际修改范围为上述五个文件；未增加程序路径校验或修改科学计算实现。
- 使用本机 TinyLensGpu 环境 `python`：启动器测试 7 项通过；最终全量测试 275 项通过（98.27 秒）。
- Shell 语法、仓库要求的 Python 语法检查、技能格式检查、Git 差异格式检查均通过；`git check-ignore` 确认仓库 `tmp/` 下的示例路径被忽略。
- 仓库未配置独立类型检查工具；此次没有 Python 实现修改。
- 独立规范审查发现一项旧行为描述的时态问题，已修正；独立需求审查没有发现问题。
- 未运行真实 Lens Run 或 GPU 建模。规则约束依赖 agent 遵循指令，测试不证明大模型不会写错位置。
